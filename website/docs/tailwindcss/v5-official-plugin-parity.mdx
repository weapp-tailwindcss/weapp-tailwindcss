# v5 与官方 Tailwind 插件对照

v5 generator 的目标不是替代 Tailwind CSS v4 的 CSS-first 语义，而是在同一份 Tailwind 输入上增加小程序专用输出能力。`target: 'web'` 应与官方 Tailwind 浏览器产物保持同源；`target: 'weapp'` 则在同一 classSet 基础上生成小程序需要且兼容的 CSS。

## 一一对应矩阵

| 能力 | `@tailwindcss/vite` | `weapp-tailwindcss/vite` |
| --- | --- | --- |
| CSS-first 入口 | `@import "tailwindcss"` | 同一入口 |
| `@source` 扫描 | 扫描模板和脚本 | 通过 `cssEntries` 绑定入口并复用 v4 source |
| `@theme` / `@config` | 生成 Tailwind token | 复用同一 token |
| 候选类生成 | Scanner candidates | runtime classSet 精确命中 candidates |
| Web 产物 | 浏览器 CSS | `target: 'web'` |
| 小程序产物 | 不支持 | `target: 'weapp'` |
| Web CSS 兼容降级 | 由 Web 目标和浏览器工具链决定 | 环境/preset 推断的 Web 与 uni-app H5 保留旧兼容默认；纯 Web 显式 `target: 'web'` 保留官方语义，`generator.webCompat` 可显式选择 |
| 失败处理 | 编译失败即失败 | 默认构建失败 |
| 依赖追踪 / HMR | `addWatchFile` / `hotUpdate` | `cssEntries` / dependencies / HMR |

在纯 Web 的显式 Web target 下，`weapp-tailwindcss` 与 `@tailwindcss/vite`、`@tailwindcss/postcss` 对齐 Tailwind CSS v4 的 CSS-first 语义。对齐范围包括 `@theme`、`@source`、层、嵌套规则、现代颜色函数、响应式和交互选择器。`weapp-tailwindcss` 额外负责多端入口发现、classSet 精确命中、构建图依赖和小程序 CSS 转换。框架或环境推断的 Web 构建以及 uni-app H5 为保持上一版本行为仍默认走 `legacy-web` 兼容降级。

需要官方 Web 产物时，纯 Web 项目使用显式 `generator.target: 'web'` 或 `weapp-tailwindcss/vite/web` 专用入口并省略 `webCompat`；uni-app H5 需要显式传入 `generator.webCompat: false`。旧 WebView 需要降级时显式设置 `generator.webCompat: true`，或传入 `{ preset: 'legacy-web' }`。这一步会降低现代 CSS 语法，不属于官方 Web 产物。

需要更细粒度的兼容策略时，使用 `webCompat.policy` 为 `@theme`、`@layer`、nesting、selectors、typed division、calc、variables、units、现代颜色和 at-rule 分别选择 `preserve`、`lower`、`warn`、`error` 或 `remove`。目标可以显式传入，也可以由 Vite 的 `cssTarget` 或 `build.target` 提供。目标只参与能力判断和诊断，不会单独改变官方 Web 输出。

## Vite 对照

官方写法：

```ts title="vite.config.ts"
import tailwindcss from '@tailwindcss/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    tailwindcss(),
  ],
})
```

v5 小程序写法：

```ts title="vite.config.ts"
import path from 'node:path'
import { defineConfig } from 'vite'
import { WeappTailwindcss } from 'weapp-tailwindcss/vite'

export default defineConfig({
  plugins: [
    WeappTailwindcss({
      cssOptions: {
        rem2rpx: true,
      },
      cssEntries: [
        path.resolve(__dirname, 'src/app.css'),
      ],
    }),
  ],
})
```

同一个构建中不要再同时注册 `@tailwindcss/vite`、`@tailwindcss/postcss` 和 `WeappTailwindcss` 生成同一份 Tailwind CSS。如果项目需要 H5 / Web 产物，可以在独立的 Web 构建里继续使用官方 Tailwind 插件；如果要用 `weapp-tailwindcss` 做 Web 对照测试，则把 `generator.target` 显式切到 `web`，此时保留浏览器选择器、hover media、层、嵌套规则和原始 Tailwind 转义。小程序生产构建切回默认 `weapp`。

## 回归测试

仓库使用 `packages/weapp-tailwindcss/test/v5/official-tailwind-plugin-parity.test.ts` 覆盖这张矩阵：

- 同一 CSS-first 输入在 `target: 'web'` 下，核心 utility selector 与官方 Tailwind 产物保持一致。
- 矩阵中的 `@tailwindcss/vite` 与 Vite generator 两列必须全部有对应项。
- Tailwind CSS 4 快速开始页和 v5 迁移指南继续覆盖 uni-app Vue Vite、Taro Vite 与 Mpx 的真实 demo 配置。
- 这些对照项应通过你的目标项目构建产物和真实运行时检查，确保示例代码与最终样式一致。
