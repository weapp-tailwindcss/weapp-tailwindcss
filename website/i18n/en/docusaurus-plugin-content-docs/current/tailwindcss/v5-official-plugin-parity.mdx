# v5 Compare with official Tailwind plug-in

The goal of the v5 generator is not to replace the CSS-first semantics of Tailwind CSS v4, but to add small program-specific output capabilities to the same Tailwind input. `target: 'web'` should maintain the same origin as the official Tailwind browser product; `target: 'weapp'` should generate the CSS required and compatible with the applet based on the same classSet.

## One-to-one correspondence matrix

| Capabilities | `@tailwindcss/vite` | `weapp-tailwindcss/vite` |
| --- | --- | --- |
| CSS-first portal | `@import "tailwindcss"` | Same portal |
| `@source` scan | Scan templates and scripts | Bind the entry and reuse v4 source through
| `@theme` / `@config` | Generate Tailwind token | Reuse the same token |
| Candidate class generation | Scanner candidates | runtime classSet accurate hit candidates |
| Web Products | Browser CSS | `target: 'web'` |
| Mini program product | Not supported | `target: 'weapp'` |
| Web CSS compatibility downgrade | Determined by the Web target and browser toolchain | Environment/preset-inferred Web and uni-app H5 keep the previous compatibility default; pure Web with explicit `target: 'web'` keeps official semantics, with `generator.webCompat` available for an explicit choice |
| Failure handling | Failure when compilation fails | Default build failure |
| Dependency tracking / HMR | `addWatchFile` / `hotUpdate` | `cssEntries` / dependencies / HMR |

For pure Web with an explicit Web target, `weapp-tailwindcss` aligns with the CSS-first semantics of Tailwind CSS v4 as generated by `@tailwindcss/vite` and `@tailwindcss/postcss`. The aligned surface includes `@theme`, `@source`, cascade layers, nesting, modern color functions, responsive variants, and interaction selectors. `weapp-tailwindcss` additionally handles multi-entry discovery, exact classSet matching, build-graph dependencies, and mini-program CSS conversion. Framework or environment-inferred Web builds and uni-app H5 retain the previous `legacy-web` compatibility default for behavioral compatibility.

For official Web output, pure Web projects can set `generator.target: 'web'` explicitly, or use the dedicated `weapp-tailwindcss/vite/web` entry without `webCompat`. For uni-app H5, pass `generator.webCompat: false` explicitly. When an older WebView needs a downgrade, set `generator.webCompat: true` or pass `{ preset: 'legacy-web' }`. This lowers modern CSS syntax and is not part of the official Web output.

Use `webCompat.policy` for per-capability control over `@theme`, `@layer`, nesting, selectors, typed division, `calc`, variables, units, modern colors, and at-rules. Each capability supports `preserve`, `lower`, `warn`, `error`, or `remove`. Targets can be explicit or supplied by Vite `cssTarget` and `build.target`. Targets drive capability checks and diagnostics without changing official Web output on their own.

## Vite comparison

Official writing:

```ts title="vite.config.ts"
import tailwindcss from '@tailwindcss/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    tailwindcss(),
  ],
})
```

v5 applet writing method:

```ts title="vite.config.ts"
import path from 'node:path'
import { defineConfig } from 'vite'
import { WeappTailwindcss } from 'weapp-tailwindcss/vite'

export default defineConfig({
  plugins: [
    WeappTailwindcss({
      cssOptions: {
        rem2rpx: true,
      },
      cssEntries: [
        path.resolve(__dirname, 'src/app.css'),
      ],
    }),
  ],
})
```

Do not register `@tailwindcss/vite`, `@tailwindcss/postcss`, and `WeappTailwindcss` together to generate the same Tailwind CSS in one build. If the project requires H5/Web products, you can continue to use the official Tailwind plug-in in a separate Web build. If you want to use `weapp-tailwindcss` for Web control testing, set `generator.target` to `web` explicitly. The output then retains browser selectors, hover media, layers, nesting, and original Tailwind escapes. Switch the mini program production build back to the default `weapp`.

## Regression testing

The warehouse uses `packages/weapp-tailwindcss/test/v5/official-tailwind-plugin-parity.test.ts` to overwrite this matrix:

- The same CSS-first input under `target: 'web'`, the core utility selector is consistent with the official Tailwind product.
- The two columns `@tailwindcss/vite` and Vite generator in the matrix must all have corresponding entries.
- Tailwind CSS 4 quick start page and v5 migration guide continue to cover real demo configurations of uni-app Vue Vite, Taro Vite and Mpx.
- Verify these comparisons through your target project's build artifacts and real runtime behavior so the sample code stays aligned with the final styles.
