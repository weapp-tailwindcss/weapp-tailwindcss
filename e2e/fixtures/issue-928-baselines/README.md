# Issue 928 截图基线

`v4-compare.png` 按运行时 CSS 像素坐标采样，区域为三个定位节点的并集，加 2 CSS 像素边距。当前布局的区域尺寸是 240×128 CSS 像素，渐变块为 112×56 CSS 像素。

截图物理分辨率由 DevTools 决定，不能直接用它作为基线尺寸。`e2e/issue-928/css-pixel-region.ts` 使用当前运行时视口宽度换算截图坐标，不读取基线尺寸来缩放当前布局。因此真实 CSS 尺寸变化仍会导致尺寸断言失败。

像素基线拒绝非整数采样比例。旧基线来自 640 物理像素 / 390 CSS 像素的截图，原视口已含约 1 CSS 像素的竖向偏移；CSS 坐标归一化不能还原丢失的截图几何。当前基线在 macOS、微信 DevTools Stable 2.02.2608080、项目基础库 3.10.3、iPhone 6/7/8 模拟器（375×667 CSS 像素）、官方菜单「显示比例 → 100%」下采集。原图 750×1334，视口 750×1206，采样比例为 2，布局节点与旧基线相同。整数检查用于拒绝已知不可靠采集，不保证其他显示环境或渲染器与此基线等价。

缩放按完整项目路径保存；换 worktree 后需重新确认。保持足够窗口空间，避免截图实现再次缩小画面；出现尺寸或采样比例错误时按[多端手册](../../LOCAL-MULTI-PLATFORM-E2E.md#微信像素截图的显示比例)恢复，不修改账号、IDE 存储或截图阈值。

更新仅使用 `E2E_UPDATE_ISSUE_928_BASELINE=1 pnpm e2e:ide:issues-909-916-928`，并在同一环境取消该变量重跑验证。基线更新不是通过验收；仍需结构、颜色和像素差异断言全部通过。历史 `v3-compare.png` 不参与当前 v4 两个场景的比较。
