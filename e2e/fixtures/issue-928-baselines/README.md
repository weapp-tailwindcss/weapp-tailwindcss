# Issue 928 截图基线

两份 v4 基线按运行时 CSS 像素坐标采样，区域为三个定位节点的并集，加 2 CSS 像素边距。当前布局的区域尺寸是 240×128 CSS 像素，渐变块为 112×56 CSS 像素。

| 实际截图宽度 / CSS 视口宽度 | 唯一基线 | 采集条件 |
| --- | --- | --- |
| 1 | `v4-compare-1x.png` | 2026-10-16，1920×1080 宿主，375×667 原图、375×603 视口 |
| 2 | `v4-compare.png` | 保留 2026-10-05 原基线，750×1334 原图、750×1206 视口 |

1920×1080 和 3840×2160 宿主均可使用已登记的 1x/2x 采样条件。4K 普通模式也可能产生 1x，HiDPI 模式可能产生 2x；选择依据始终是本轮截图与运行时视口比例，不使用宿主分辨率或 `wx.pixelRatio`。同一页面的圆角抗锯齿会随栅格密度变化，两种密度分别比较，不跨密度寻找最小差异，也不放宽 `threshold: 0.1` 或差异像素 `<10`。

截图物理分辨率由 DevTools 决定，不能直接用它作为基线尺寸。`e2e/issue-928/css-pixel-region.ts` 使用当前运行时视口宽度换算截图坐标，不读取基线尺寸来缩放当前布局。因此真实 CSS 尺寸变化仍会导致尺寸断言失败。

像素基线拒绝非整数和未登记采样比例。旧基线来自 640 物理像素 / 390 CSS 像素的截图，原视口已含约 1 CSS 像素的竖向偏移；CSS 坐标归一化不能还原丢失的截图几何。两份当前基线均在 macOS、微信 DevTools Stable 2.02.2608080、项目基础库 3.10.3、iPhone 6/7/8 模拟器（375×667 CSS 像素）、官方菜单「显示比例 → 100%」下采集。整数检查用于拒绝已知不可靠采集，不保证其它渲染器与此基线等价。

缩放按完整项目路径保存；换 worktree 后需重新确认。保持足够窗口空间，避免截图实现再次缩小画面；出现尺寸或采样比例错误时按[多端手册](../../LOCAL-MULTI-PLATFORM-E2E.md#微信像素截图的显示比例)恢复，不修改账号、IDE 存储或截图阈值。

更新仅使用 `E2E_UPDATE_ISSUE_928_BASELINE=1 pnpm e2e:ide:issues-909-916-928`，只写当前采样条件对应的基线；审图后在同一环境取消该变量重跑验证。普通验证遇到缺失、损坏或未登记的基线直接失败，不自动初始化或回退。基线更新不是通过验收；仍需结构、颜色和像素差异断言全部通过。历史 `v3-compare.png` 不参与当前 v4 两个场景的比较。

`captures/` 保存真实 1x/2x 视口原图、运行时和几何记录，用于不启动 IDE 的入口回归；原图未缩放或重采样，来源及 SHA-256 见 `captures/provenance.json`。历史 2x 采集的准确提交和独立原执行日志缺失，离线回归不能替代本轮 4K 显示环境的真实验收。详见[密度基线复盘](../../../docs/engineering/lessons/wechat-screenshot-density-baselines.md)。
