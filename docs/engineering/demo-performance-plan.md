## 三组对照

| 模式 | 输入与接入方式 | 解释范围 |
| --- | --- | --- |
| 原生基线 | 移除 weapp-tailwindcss 接入及专属依赖，保留可运行框架页面 | 完整接入成本；不保证样式等价 |
| 等价静态基线 | 不加载插件，使用计时前生成的普通 CSS 和匹配的安全类名 | 同等页面效果下的实时处理成本 |
| 正常接入 | 当前真实 demo 配置 | 用户实际承担的成本 |

固定框架、工具链和共有依赖版本，三组分别隔离目录、缓存、输出及进程。静态输入由 weapp-tailwindcss 预生成，不引入官方 Tailwind 生成插件，不复制最终 bundle 代替框架编译。

热更新固定修改序列，为每个状态提前准备静态输入。新增样式时静态组同时修改源码与普通 CSS；其时间不包含人工编写 CSS。验证实际消费类名、页面结构、可达样式及计算样式；无法证明等价的样本不能用于公平对照。

## 指标与采样

| 阶段 | 场景 | 采样 |
| --- | --- | --- |
| 安装 | 空 store 首装、热 store 重装、已有依赖上的增量安装 | 各 7 轮 |
| 编译 | 清理项目缓存后的构建、保留缓存后的构建、dev 首次就绪 | 各 7 轮 |
| 热更新 | 文本、已有类替换、新类新增与移除、作者 CSS、配置失效与恢复 | 每类预热 2 轮，采样 20 轮 |

- 串行采样，轮换三种模式的执行顺序；记录原始样本、median、p95、绝对差值、百分比和进程树峰值 RSS。
- 每个 demo 的安装使用独立消费项目及打包后的完整内部依赖闭包，不使用 workspace 链接。记录新增依赖、包体积、安装空间和生命周期脚本成本。
- 发布版真实网络安装单独报告；本地 tarball 安装不能代表下载耗时。网络冷安装用于诊断，离线热 store 安装用于稳定门禁。
- 包自身构建和实验准备排除在编译计时外。首次有效产物、页面就绪分别记录。
- 同一 watcher 连续修改，分别记录保存到产物完成、保存到页面生效；原生热重载与真正 HMR 单列。必须匹配本轮 marker、样式和恢复状态，不能用完整重构建或固定等待代替 HMR。
- profiling 独立于验收采样运行，诊断计时默认关闭。

## 待实现的工具与门禁

计划新增脚本键 `perf:demo:report`、`perf:demo:guard`、`perf:demo:baseline:update`；当前尚未注册，不可直接运行。入口支持目标、阶段、基线提交和输出目录筛选。

报告采用带版本的 JSON，并输出中文 Markdown。包含 SHA、环境和工具链、依赖、设备身份、缓存模式、样本、语义断言与覆盖状态。缺失、超时、失败、不适用分别记录，不能以零耗时替代。原始数据默认写入忽略目录或 CI artifact。

- PR 跑各构建器、框架、样式注入和分包代表目标，并追加受影响目标；公共核心链路变化覆盖所有代表目标。
- 每日及手动工作流运行完整 CLI 矩阵，沿用现有跨系统策略。IDE 与设备使用本地或已有专用 runner；缺环境不宣称全量通过。
- PR 在同一 runner 用同一脚本比较基准与当前提交，检查正常接入总耗时及相对静态组的额外耗时。历史绝对值仅限同类环境比较。
- 耗时退化同时超过 5% 和 10 ms 才进入统计确认；RSS 同时超过 5% 和 64 MiB；离线安装采用 10% 和 250 ms。
- 疑似退化仅允许一次反向顺序完整复测，保留两次结果；不反复重跑直到通过。
- 完成首轮优化后，以两批独立采样中较高的逐目标开销加上述容差冻结预算。只能显式更新预算，普通执行和 CI 不自动放宽。

## 优化与完成条件

先取得全量基线，再按绝对额外耗时、影响目标数和操作频率排序。重点检查发布内容与依赖闭包、入口加载、重复扫描与解析、候选集合更新、缓存失效范围和重复构建。每项生产优化必须有 profile、语义回归及同口径前后结果；没有证据的方向仅作为建议。

保持精确类名命中、CSS 包职责和 bundler 生命周期边界，不以漏生成、漏更新或错误缓存换取速度。验证清单完整性、模式隔离、缓存控制、统计、门禁、超时清理、进程归属及跨平台路径。修改 demo 或产物场景时，显式更新对应 static 基线，再执行不更新基线的验证。

最终交付逐 demo／目标对照表、热点排名、安装成本清单、优化收益及后续建议。优化后重跑完整适用矩阵；所有适用项完成且没有确认退化才标记完成，不能用整体平均值掩盖单目标退化。
