# 网站本地命令按任务发现并核验进程身份

## 症状

新图片解码合同的完整黄金采集在第 636/1806 项失败。网站本地命令的运行期身份查询 `ps 91087` 耗尽原 5000ms 预算，收尾查询 `ps 91108` 也超时；执行和清理错误均保留。候选没有生成原生报告或 manifest，不能比较、审查或安装。原日志 SHA256 为 `4d4d70dfe37de221843bea96c746d3b43c14d2d8822e01b31f91a7da764a1875`。

## 根因与纠正

生命周期适配器把 tracker 的 `subset` 请求转回全表读取，忽略了传入的 PID。启动 gate 放行后，两个本地命令各自约每 100ms 查询全机的启动时间和状态；根进程退出后的清理也重复该路径。这是已确认的查询范围问题，尚不能证明它是宿主此次超时的唯一原因。

POSIX 改为全局读取 PID/PPID/PGID 关系，从本轮根、已登记身份入口和原进程组展开候选，再只读取候选的启动身份和状态。详情之后复查轻拓扑；新增后代、reparent 或切组需要在同一个截止内重采。新见候选仍存在却失去发现锚时明确拒绝，不能静默返回空归属。大子树分批详情后复核父锚出生身份，避免把早批旧父和晚批新子代拼成可信关系。真正领取归属仍由原 `collectOwnedProcesses` 的出生身份、父关系和进程组锚规则决定。

启动握手仍只登记本次 spawn 根身份；Windows 保留已有观察器路径。拓扑、详情、复核和重采共享原 5 秒预算，迟到结果不能回写。每轮查询共用一个 owner 并排空后释放回执；未确认回收的首错在命令域锁存，后续轮次在创建探针前拒绝，避免长时间采集积累全部历史查询。

核心查询、原身份和命令回归共 49 项通过，网站类型检查通过。新增真实 Worker 用例确认请求内容、周期扫描和根进程退出；把同一用例绑定旧生命周期实现时，在禁止全机详细查询处实际失败，修复实现通过。旧实现仅在隔离临时 harness 中使用，未替换工作树源码；第一次 harness 因 mocks 入口配置失败、未执行用例，修正后才得到有效负对照。

本地命令 11 文件 97 项通过。新增真实进程图先登记根和独立组锚，等待根退出，再请求锚创建另一个独立组后代；仅以已登记锚发现新后代，最终核对出生身份、凭据端口和收尾，通过。

进程图夹具首次收尾失败：它提前断开锚与叶的 IPC，之后又等待该 ChildProcess 的 `close`。Node 24.22.1 的独立两臂实测中，提前断开的一臂有 `exit=0`，原 2 秒内没有 `close`，内部关闭计数为 1/2；保留连接的一臂有 `exit=0` 和 `close`，计数 2/2。夹具保留锚与叶的 IPC 至叶自行退出；独立组关系仍由实际 PGID 证明。没有调整预算，也没有把该 Node 版本下的现象推广为所有版本的内部根因。失败目录与原错误保留，后续定向核对两个业务 PID 均不存在。

包含真实进程图的最终本地命令 12 文件 98 项通过，六个改动 TypeScript 文件 lint 及网站类型检查通过。额外尝试独立严格 tsc 时，首次缺少 TypeScript 6 要求的 `--ignoreConfig`，补齐后又缺显式 Node 类型并暴露既有传递依赖的精确 optional 类型问题，不能记为该检查通过；实际网站项目类型检查保持成功。网站完整采集、黄金审查、禁止更新验收及新 head CI 尚未通过，记录保持 partial。

## 适用边界

轻拓扑不是原子的系统快照。任意两个观察点之间出生、退出并失去全部活锚的未登记 double-fork，仍不在归属证明范围内。此次改动只覆盖网站本地命令的 POSIX 身份查询，不改变外层内存采样或全仓其他进程观察器，也不提高任何执行、回收或像素门槛。

失败后原服务端口已无监听；历史 PID 核查中仍出现的数字属于更晚出生的其他进程，未发送信号。最终 Firefox PID 未被历史采样保存，不能把定向核查写成所有后代均已独立确认退出。

## 规则评估

现有规则已要求按身份清理、保留首错和严格截止，无需新增全局禁令。通过持久回归约束查询范围、跨阶段预算和身份边界。
